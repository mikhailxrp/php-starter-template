## Дизайн: образцы и стили

Дизайн проекта сделан заранее в `design-template`. Публичные страницы используют **наш CSS из дизайна** (Bootstrap на них не подключаем). Админка использует Tabler с нашими цветами.

### Где что лежит

```
.docs/
├── design/                  ← tokens.json, direction.md, tokens-report.md
└── ref/
    └── prototypes/          ← образцы экранов (HTML), только для чтения

public/assets/
├── css/
│   ├── main.css             ← подключает всё остальное (публичная часть)
│   ├── base/vars.css        ← токены (сгенерирован, руками не править)
│   ├── components/          ← кнопки, поля, карточки и т. д. (BEM)
│   ├── packs/               ← компоненты под тип проекта
│   └── admin-theme.css      ← подмена цветов Tabler (подключается ПОСЛЕ tabler.min.css)
├── fonts/                   ← шрифты проекта
├── js/ui.js                 ← меню, окна, аккордеон (Vanilla JS)
└── vendor/tabler/           ← Tabler (только админка)

src/Views/
├── layout/                  ← общие части: header.php, footer.php
├── pages/                   ← страницы публичной части
└── admin/                   ← админка (свой макет на Tabler)
```

Если `.docs/design/` или `.docs/ref/prototypes/` нет, дизайн не подключён. Не придумывай вид интерфейса: спроси, откуда его брать.

### Как превратить образец в PHP-шаблон

1. Открой образец в `.docs/ref/prototypes/` и его состояния (`--empty`, `--error` и т. д.).
2. Блоки, помеченные в образце `<!-- @include header -->` … `<!-- @end -->`, вынеси в `src/Views/layout/` (`header.php`, `footer.php`) и подключай через `render()`.
3. Скопируй разметку страницы в `src/Views/pages/<имя>.php`. **Классы не меняй.**
4. Пути: `../assets/…` → `/assets/…`. Ссылки `catalog.html` → маршруты из `config/routes.php`.
5. Подставь данные: тексты-заглушки заменяются переменными (`<?= e($title) ?>`). Цикл по готовому массиву, который передал контроллер, допустим. Запросов к БД во Views нет.
6. Формы: внутри `<form method="post">` добавь `<?= csrfField() ?>`. Ошибки и сообщения об успехе берутся из флеш-сообщений (`setFlash()` / `getFlash()`), как в образцах состояний.
7. Добавь все состояния экрана: пусто, ошибка, успех (если есть данные — загрузка).

### Что нельзя

- Писать стили в `style=""` и в `<style>` внутри Views.
- Править `public/assets/css/base/vars.css`: он генерируется. Цвета и размеры меняются в `.docs/design/tokens.json`, пересборка делается в `design-template` (`python tools/build_tokens.py`), потом копируется новый `vars.css`.
- Писать цвета, радиусы, тени в CSS как HEX и пиксели: только `var(--…)`.
- Менять классы компонентов в разметке «под себя». Нужного компонента нет: добавь файл в `public/assets/css/components/` (BEM, только токены, без `!important`, с состояниями hover, focus, disabled) и подключи в `main.css`.
- Копировать в проект заглушки картинок из прототипов (SVG-заглушки): они временные.

### Админка (Tabler)

- Подключение: сначала `/assets/vendor/tabler/css/tabler.min.css`, потом `/assets/css/admin-theme.css`.
- Макет админки лежит отдельно: `src/Views/admin/layout/`. Публичный CSS (`main.css`) в админке не подключаем.
- Если образец админки сделан на классах Tabler, используй их как есть: они работают с локальным Tabler. Если образец сделан на наших компонентах, собери экран из готовых компонентов Tabler и не дублируй их своими.
- Графики: ApexCharts из `public/assets/vendor/tabler/libs/`.
- Версию Tabler не обновляй вручную по частям.

### Как делать UI-задачу

1. В `TASK.md` указан образец: файл из `.docs/ref/prototypes/`. Не указан — найди по названию экрана. Подходящего нет — скажи об этом и не придумывай дизайн.
2. Сделай шаблон по шагам выше.
3. Все выводимые данные через `e()`.
4. Проверь на ширине 360 px, 768 px и 1280 px. Зоны нажатия не меньше 44 px.
5. В отчёте по таску перечисли расхождения с образцом и причину.

### Если образец и данные расходятся

Расположение и состав блоков берём из образца. Если в данных нет того, что в образце (например, нет картинки), блок выводится без неё, без выдуманного содержимого, а расхождение попадает в отчёт.
